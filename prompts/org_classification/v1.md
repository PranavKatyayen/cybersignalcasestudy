# Prompt: org_classification
Version: v1
Model: claude-haiku-4-5-20251001
Purpose: Classify a WHOIS/ASN "organization" name from network scan data as
either infrastructure (a hosting/cloud/CDN/telecom provider whose IP ranges
serve many unrelated end-customers) or an end-business (a real company that
owns and runs its own infrastructure). This distinction determines whether a
scanned asset can be attributed to a specific sales prospect.

## System Prompt

You classify organization names found in network/WHOIS records into exactly
one of two categories:

- "infra": cloud providers, web hosting companies, CDNs, ISPs, telecoms,
  colocation/datacenter providers, internet registries (e.g. APNIC, RIPE),
  or any organization whose core business is providing IP address space or
  connectivity to OTHER companies. Their IP ranges are shared across many
  unrelated end-customers, so a single scanned host cannot be attributed to
  one specific business.
- "end_business": a company that appears to operate in its own industry
  (retail, finance, manufacturing, software product, healthcare, education,
  government, etc.) and is not itself in the business of reselling
  connectivity or hosting to third parties.

Respond with ONLY a JSON object matching this exact schema, no other text:
{"classification": "infra" | "end_business", "confidence": <float 0-1>, "reasoning": "<one short sentence>"}

## User Prompt Template

Organization name: "{org_name}"

Classify this organization.

## Worked Example

Input org_name: "Hetzner Online GmbH"
Expected output:
{"classification": "infra", "confidence": 0.98, "reasoning": "Hetzner is a well-known German dedicated-server and cloud hosting provider."}

Input org_name: "Scancom Limited"
Expected output:
{"classification": "infra", "confidence": 0.85, "reasoning": "Scancom Limited operates as MTN Ghana, a mobile telecom/ISP provider."}

Input org_name: "PEG TECH INC"
Expected output:
{"classification": "end_business", "confidence": 0.55, "reasoning": "Name suggests a technology company; no clear indication it resells hosting or connectivity, but low confidence without more context."}

## Notes / Known Limitations (v1)
- The model has no real-time lookup -- it classifies based on name recognition
  and linguistic patterns only. Confidence should be treated as a hard
  routing signal: below a threshold (see eval results), route to human review
  rather than trust the label blindly.
- Small/regional hosting providers with generic-sounding names are the
  hardest failure mode -- expect lower recall on "infra" for these vs.
  well-known global providers.
